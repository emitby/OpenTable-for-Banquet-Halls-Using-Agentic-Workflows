What it does

A customer describes an event in plain language, for example "a wedding for about 180 guests in Austin, Texas next October, budget around $45,000". The Concierge agent works out what's needed and delegates: the Venue Scout searches venues in that state and checks dates, and the Pricing Analyst builds itemized quotes with that state's sales tax. The customer sees venue cards and exact quotes, can ask for a free 72-hour hold, and confirms the booking themselves. No agent can commit the customer to a purchase.

3. Agentic workflow

One customer turn: the Concierge delegates to the specialists (in parallel when it needs both), each specialist works in a fresh context and returns only a summary, and every reply passes the price-grounding check before the customer sees it. Guardrails are shown where they apply.

AgentEffortTools (least privilege)Job
Conciergemediumask_venue_scout, ask_pricing_analyst, check_availability, show_venues, place_holdTalks to the customer, delegates, shows cards, places holds
Venue Scoutlowsearch_venues, get_venue_details, check_availabilityFinds and shortlists venues in the right state (read-only)
Pricing Analystlowget_venue_details, build_quotePrices options and compares them to the budget (read-only)

A turn, step by step

  1. G1 checks the message. Injection attempts are answered without any model call.
  2. The Concierge calls ask_venue_scout with a self-contained brief (state, city, guests, date, budget).
  3. The Venue Scout runs search_venues (with the state filter) and check_availability, and returns a shortlist with ids.
  4. The Concierge calls show_venues (cards) and ask_pricing_analyst together; the Pricing Analyst runs build_quote for each option.
  5. The Concierge writes the reply; G4 checks every dollar amount against the tool results. On request it places a hold (G3 checks); confirming is the customer's action only (G7).

4. Guardrails

Prompts describe the rules so the agents usually comply first time, but every guardrail is enforced in code and tested in both directions (the bad case is blocked, and the harmless look-alike, such as "please ignore the previous date", still works).

#GuardrailWhat it doesWhere
G1Customer inputStrips control characters, limits length, and politely refuses prompt-injection phrasing before any model call (zero cost).ConciergeSession.send
G2Tool argumentsEvery tool call is checked against the tool's JSON schema (types, ranges, required fields, no extra fields) before it runs; problems go back to the agent as fixable errors.Agent._execute
G3HoldsAt most 3 active holds per conversation, and the email must be one the customer actually typed, so an agent can't invent or reuse one._place_hold
G4Price groundingEvery dollar amount in the Concierge's reply must match a dollar amount from a tool result (a money field such as a quote total, or a $-figure in a specialist's reply) or the customer's own words, at the precision written. Guest counts, ids and percentages never count. Otherwise the reply is sent back once; if it's still wrong, a warning is added.ConciergeSession.send
G5PrivacyEmails are replaced with <email> in traces and run reports. (Customers still see their own email on their own screen.)harness.trace
G6Token budgets400,000 tokens per customer turn and 2,000,000 per conversation, checked before every model call.Agent.run
G7Human-only commitmentsNo agent has a confirm or cancel tool. Only the customer can confirm (API, web button or CLI after y/N).team.py, api.py

Host safety (CLAUDE.md): no os module, paths and temporary files kept in the project folder, no file deletions, the server bound to 127.0.0.1, and security headers on every response. Source scans in the test suite enforce these.

5. The harness

The harness wraps the agent team without changing it. The runtime emits an event for every model call and tool call; the harness records, measures and scores them.

PartWhat it does
Runtime eventsmodel_call (agent, usage, latency, stop reason, tools requested and their argument sizes), tool_call, tool_result (ok/error, latency, result size) and guardrail events. A specialist's events carry the id of the delegation call that started it.
Traceruns/<id>/<scenario>/trace.jsonl: every event, emails redacted (G5).
Token ledgerExact usage per agent; attributed usage per tool (see below); cost at the configured claude-opus-5-5 prices.
ScenariosNine scripted conversations: Texas wedding with a hold, Ohio corporate dinner, NYC gala on a booked date, a Denver price guess (G4), a hold without an email (G3), an off-topic request and an injection (G1), a DC baby shower, a Wyoming reunion (state given by name) and an oversized message (G1).
Scorerscompleted · venues_in_state · prices_grounded · expected_guardrails · holds · read_only_specialists · no_tools_when_declining · within_budget
ModesSimulated: free, offline, scripted agents, estimated tokens. Live: real Claude agents, real usage, a cost cap (default $5) checked between scenarios. In live mode, G3 and G4 may fire but aren't required, since real agents rarely misbehave on cue.

How tokens are attributed to tools

The API reports usage per model call, not per tool, so the ledger attributes it:

  • Decision: the output tokens of the call that requested the tool (reasoning plus writing the call), split by argument size when several tools are requested at once.
  • Result: how much the agent's prompt grew on its next call, minus the previous output, split by result size: the cost of reading the tool's output.
  • Specialist: for ask_venue_scout and ask_pricing_analyst, everything the delegated agent used.

Per-agent totals are exact sums of reported usage; per-tool numbers are an attribution. If an API version leaves earlier reasoning out of later prompts, result tokens are understated (the subtraction assumes the previous output stays in the history).

Limits

  • Venues are fictional. Sales tax is the state base rate (approximate; local and meals taxes are not modeled), except the original New York and New Jersey venues, which use combined local rates.
  • The injection check catches known phrasings; the agents' instructions are the second line of defense.
  • Token budgets are checked before each call; two specialists running in parallel can overshoot by one call each.
  • Price grounding checks the Concierge's reply; arithmetic inside a specialist's reply is accepted as evidence.
  • Per-tool token numbers are attributions; the numbers in this guide are simulated estimates.
  • Sessions live in memory; there are no payments or accounts, and confirmation is checked by email match only.
